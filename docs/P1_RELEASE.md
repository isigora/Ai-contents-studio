# P1 제작 확장 — 구현 및 검증 기록

최상위 기준: Master_Development_Specification.md v1.0. 원본과 공개 홈페이지 문구·레이아웃을 유지했습니다.

## 이번 구현

- 승인 요청 → 소유자 승인/수정 요청 → 회수. 승인된 문구는 새 버전으로 고정됩니다. 편집하면 승인 상태를 초기화하고 이력을 남깁니다. 오래된 원천 정보로는 승인할 수 없습니다.
- 웹사이트, Instagram, 微信, LinkedIn, 이메일 템플릿. 채널별 형식 선택 제한, 제안서와 영상 대본 형식 추가. 글자 수는 편집 권장값이며 공식 플랫폼 한도나 API 연동을 뜻하지 않습니다.
- 선택한 과거 버전의 문구와 원천 스냅샷을 별도 초안으로 재사용. 승인 상태는 복사하지 않습니다.
- 보유 사진을 사용하는 1080×1080 및 1080×1920 PNG 카드, 720×1280 H.264 9초 무음 MP4, UTF-8 SRT. 세 장면 각 3초. 문구는 저장한 버전의 발췌만 허용하며 사진 사용권 메모가 필요합니다.
- 미디어는 별도 검토가 필요한 DRAFT입니다. 원문이 승인되었어도 미디어의 승인으로 간주하지 않습니다. 사진과 콘텐츠 버전, 제작 설정, 파일 목록을 보존합니다. 다운로드는 동일 Workspace 인증을 요구합니다.
- UI 한국어/중국어/영어 선택과 335개 번역 항목. 콘텐츠와 사용자가 입력한 자료는 UI 언어 변경으로 변환하지 않습니다. 서버의 일부 상세 오류·근거 누락 진단은 한국어 원문으로 표시됩니다. 외국어 본문은 등록된 승인 번역을 사용하며 누락은 표시합니다. 유료 번역 AI는 연결하지 않았습니다.
- 재실행 가능한 추가 DB 마이그레이션, 기존 데이터 보존, DB와 파일의 백업·복원 명령.

## 실제 경로

`/studio` → 콘텐츠 스튜디오 → 채널/형식 선택 → 생성·저장.
콘텐츠 보관함 → 문서 → `승인·재사용` 또는 `미디어` 탭.
미디어: 자산 메뉴에서 사용권 메모와 함께 사진 업로드 → 문서 저장 → 사진/발췌 3개 선택 → 제작 → PNG/MP4/SRT 다운로드.
상단 언어 선택은 화면 언어만 바꿉니다.

## 검증 결과

- 기존 P0 18개와 P1 8개, 총 서버 수용 테스트 26개 PASS. 실제 Better Auth와 디스크 기반 PGlite, Request/Response 경계를 검사했습니다.
- P0→P1 스키마 반복 적용, 백업/복원, 별도 프로세스 재열람, 기존 자료가 있는 복원 대상 거부: 4개 PASS.
- 실제 승인·미디어 컴포넌트의 3개 언어 SSR 및 번역 사전 검사 PASS.
- 실제 브라우저에서 로그인 전 UI의 한국어→영어 전환 확인. 인증 정보를 입력하지 않았습니다.
- 실제 승인 화면 컴포넌트에 명시적 예시 데이터를 넣은 정적 렌더링을 확인. 320px/390px 프레임에서 document scrollWidth와 clientWidth가 각각 320/320, 390/390으로 가로 넘침 없음. 실제 iPhone 또는 로그인 E2E 테스트를 대신하지 않습니다.
- 실제 PNG와 MP4 생성. ffprobe로 영상 길이 9초, 720×1280, H.264 확인. 예시는 실제 제품 사진이 아닌 단색 테스트 이미지입니다.
- TypeScript 검사와 Next.js 프로덕션 빌드 PASS.

## 추가 실행 환경

P0와 동일한 Node.js 24 + pnpm 환경입니다. 검토용 DB는 내장 PGlite이며 별도 PostgreSQL 설치가 필요 없습니다. P1의 MP4에는 FFmpeg(libx264 지원)가 추가로 필요합니다. PNG와 글 생성에는 FFmpeg가 필요하지 않습니다. 한국어·중국어·영어 글꼴은 `vendor/fonts`에 동봉하고 OFL 라이선스를 포함합니다.

```bash
pnpm install --frozen-lockfile
pnpm setup:local
pnpm dev
```

브라우저 `http://localhost:4173`. 실행 중 터미널을 열어 두세요. `Ctrl+C`로 종료합니다.

기존 사용자는 앱 종료 후 `.data`와 `.env.local`을 백업·보존하세요. 새 프로젝트 폴더에서 `LOCAL_DATA_DIR`을 기존 자료의 절대경로로 설정하거나 자료 폴더를 복사하세요. 원래 폴더를 지우거나 여러 프로세스에서 같은 PGlite DB를 동시에 열지 마세요. 로컬 모드에서는 새 테이블을 자동 추가합니다. 외부 PostgreSQL은 백업 후 `pnpm db:migrate`가 필요합니다.

```bash
pnpm test
pnpm typecheck
pnpm build
# 앱을 종료한 상태에서:
pnpm backup:local /절대경로/backup
pnpm restore:local /절대경로/backup /절대경로/빈복원폴더
```

FFmpeg가 없으면 영상 제작은 실패로 기록되며 원천 자료는 유지됩니다. 설치 후 새 요청으로 재시도하세요. 장시간 제작은 동기 요청으로 처리하므로 운영 프록시 시간 제한을 검토해야 합니다. Workspace당 진행 중 작업 1개, 분당 요청 3개, 프로세스당 렌더링 2개 제한입니다. 운영용 분산 작업 큐는 아직 없습니다.

## 시제품 재사용 검토

기존 Python 시제품의 세 장면×3초 슬라이드/SRT 원칙을 TypeScript 작업자로 포팅했습니다. 공개 출력 폴더나 무인증 서버는 재사용하지 않았습니다. Sharp의 안전한 이미지 디코딩과 Pango 텍스트 렌더링, 인자 배열 기반 FFmpeg 실행을 사용합니다. 사용자 문자열을 shell이나 SVG 코드로 실행하지 않습니다.
